Work

  • This fall, I'm interning on the Journal team at Amazon Web Services. Journal is a fault-tolerant, high performance, durable write-ahead log service at massive scale, handling over 100M transactions per second. Journal is regularly used as a tier-0 building block for other AWS services. For example, Journal enables S3 and DynamoDB to durably record changes before applying them.

    My project detects and isolates single-host failures in Journal Stream Router (JSR), the fleet that routes clients to the Journal backend. A JSR host with failing hardware can keep accepting connections while serving them poorly, hurting every client routed to it. I built a system that watches each host's kernel logs for signs of hardware failure and quarantines a failing host. A quarantined host stops accepting new connections and gradually drains its existing connections to healthy hosts. To protect fleet capacity, hosts coordinate through a shared lease. Only one host can be quarantined at a time, and only when enough healthy hosts remain to absorb its traffic.

    I’m approaching the end of my internship, and I’m excited to see the results of my work once it’s productionized! I’ve been able to catch a whole host of errors during beta testing, and I’m hoping my work will reduce the oncall load by catching failing hosts before Journal sees customer impact.

  • Over the summer I was at Lockheed Martin, where I rebuilt the communications org’s search engine, which previously ran on Algolia. The old engine often missed valid results for domain-specific queries, with searches using an acronym, internal program name, or paraphrase routinely failing to surface relevant documents, often with zero results.

    To fix this, I built a search engine using OpenSearch and AWS Neptune. Using large language models, I extracted entity-relationship-entity triples from 15,000+ internal documents into AWS Neptune, producing a graph of 270K+ nodes and 1.2M+ edges. When a document is indexed, Cypher queries fetch its entities, aliases, and related concepts from the graph and store them on the document’s OpenSearch entry. Related concepts are weighted lower than direct aliases so loose matches don't crowd out exact ones.

    As a result, a search using a program's full name now finds documents that only use its acronym and also documents containing semantically related content. Compared to the same OpenSearch pipeline without the graph, this raised the top-10 search result relevance (nDCG) by 46%. Because all graph work happens at index time, searches never wait on Neptune. Serving from inside Lockheed's network instead of calling an external service also cut p95 query latency by 40% compared to Algolia.

I also built an object detection pipeline that combines YOLO with an Intel RealSense depth camera to locate objects in 3D in real time, so the robot knows where things are around it. Research

  • At the Robotarium at Georgia Tech, I worked on getting the lab's small robots to find and follow each other using nothing but their onboard cameras, with no external tracking system.

    I trained a lightweight YOLOv5-nano detector on a custom Roboflow dataset reaching 0.95 mAP for robot detection, then shrank the model by 65% with INT8 quantization in ONNX Runtime so it was small enough to run in real time on a Raspberry Pi. ROS2 nodes written in C++ read frames through libcamera and publish bounding box coordinates, which the robot used to detect and follow the robot in front of it.
